# 分轨播放尖锐重复声：局部循环误建修复

## 可复现原因

2026-10-30 的只读恢复工程中，局部循环为 `[20640,20641)`，工程 960 PPQ / 120 BPM，周期约 0.52 毫秒。标尺上方单击原先会强制生成 `start+1` 的循环，并立即启用。该周期会把音频切成近 2 kHz 的重复声，并使具有自然尾音的音符不断叠加；同期诊断日志的主输出峰值达到 12～13。

已有真实音乐分轨在正常播放时，各声部只启动一次，采样率 48 kHz、双声道；渲染线程采集与原分轨重采样混音高度相关、无削波。波形缓存只读取 PCM，本次未发现波形修改改变源音频。

在独立测试副本中复现 1 tick 循环，约四分之一秒的操作导致 4470 次音频源启动。修复后，同一测试只启动 6 个完整声部，并明确提示跳过异常局部循环。

## 修复行为

- 标尺上方单击只定位播放头。建立循环需要至少 4 CSS 像素的实际拖动，且吸附后两个端点不同；保留现有有效循环。
- 此编辑器的播放调度重复完整自然尾音，不是颗粒合成器。实时、离线与音频片段调度统一拒绝小于 50 毫秒的循环，避免高频重复与节点/尾音堆叠。
- 从旧工程读取到过短的局部循环时，本次播放跳过该循环、关闭播放循环状态并显示原因，按正常工程播放。不会覆盖源文件或自动重写保存的循环定位点；用户可重新拖出有效范围。
- 正常长度的循环、seek、片段源静音、轨道/组 mute 与 solo 保留。

## 实际输出检查

`scripts/diagnose-stem-output.mjs` 使用独立配置、隐藏窗口及已有真实分轨，不运行新模型。在现有应用资源地址下临时提供 AudioWorklet，采集送往输出设备前的真实 Web Audio 渲染 PCM，记录每个 source 的启动/停止时间。测试结束删除临时模块。没有录屏/麦克风权限或系统设置变更。

`scripts/analyze-stem-timeline.py` 按渲染线程帧号拼接数据，保留 seek 换图的静音间隙，按源文件、增益及调度生成参考，比较左右声道。不能把不同渲染图消息的到达顺序直接拼接成连续音频。

检查范围包括独立 stem、工程单轨、多轨、分轨组、solo/mute、seek、有效循环、重开和普通音符。初期 ScriptProcessor 采集存在主线程丢块假象，最终依据为 AudioWorklet 渲染线程数据。

验证覆盖 Windows Electron 的应用输出图；未录制物理 DAC、驱动或耳机后的声音，不能据此排除设备问题。工程里仍启用的示例音符轨会正常发声；本次没有自动静音或删除用户轨道。
