# Java 1.0–1.4.7 声音规则接入

0.1.21 接入十四个独立核对的正式客户端：1.0、1.1、1.2.1–1.2.5、1.3.1/.2，以及 1.4.2/.4/.5/.6/.7。与当前官方目录逐项比较后，核心规则共有 103 个正式版本 ID：44 个现代、4 个早期现代、55 个 legacy。这个数量表示选定规则的来源核对，不表示 103 版已完成世界实测。世界来源配置为 69 个；接受的游戏录音仍是 13 版、1,479 场，旧 1.12.2 的 49 个归一化候选继续排除。

原始来源分别见 [1.0–1.2.5](java-pre13-audio-audit.md)、[1.3](java-1.3-audio-audit.md)和 [1.4](java-1.4-audio-audit.md)。各版使用自己的官方客户端、原类及方法 Code 身份；已成功的原类探针和资源选择探针未因接入而重跑。

1.0–1.2.5 的可听路径经过整数块事件和客户端 listener，保留原始 double pow 转 float 的音高；普通 note=1 是 `0x3f079c7d`。1.3 以后本批客户端则由服务端命名声音包传输，63 量化后该音高是 `0x3f061862`，原始客户端字符串回调不再另发一次声音。接入时明确省略前七版的可执行 `pitchTransport`，防止描述字符串触发后版量化。

这十四版均把全局声音设置放在源增益：正实例音量先夹上界，再乘全局值，原 Library 最后再夹到 0..1；监听器默认值另列。前七版的 48 格门是当前客户端 view entity 的距离判断，静止编辑器参考不加眼高。其余七版保留独立核对的服务端传送来源与名义 1.62 参考。前七版没有借用后版 server-feet、维度过滤或移动相机等价结论。

生产比较经过真实资源加载器、合法工程、`noteAudioParameters` 和 `AudioEngine.nativeRequest`。它使用未打开的 native fixture 构造请求；原生解码和实际混音另外通过桌面流程检查。共构造 5,170 个工程请求，84 个采样对象/事件匹配，39,140 项浮点断言按来源分列：

| 组别 | 直接原输出 | 合成诊断原输出 | 默认值引用契约 | Studio 契约 |
| --- | ---: | ---: | ---: | ---: |
| 1.0–1.2.5 | 11,599 | 0 | 1,050（源码默认常量） | 3,500 |
| 1.3/1.4 | 13,179 | 140 | 4,932（实际原 getter 输出） | 4,740 |

默认值契约不冒称 AL listener 读回，Studio 契约不冒称游戏内模式。suppressed 原行不会被伪装为零增益比较。比较覆盖冻结有限输入与构造的合法工程，并非所有 IEEE-754 输入或所有工程的完备证明。独立只读复核重新建立 bundle，逐项检查原输出引用和输入闭包，并拒绝八个损坏样例。[前七版比较](verification.md)、[后七版分类](verification.md)、[独立复核](verification.md)。

首个实包发现前七版带签名的默认包游戏类与默认包解码助手冲突。修复将助手放入 `studio.nbsx.audio`，不改变客户端、签名或 PCM 算法，并清理旧构建产物。七版旧错误被逐版重现，当前十版 80 个采样成功解码，两类外部 codec 的 38 个输出与旧版逐位一致。[修复详情](java-decoder-package-fix.md)。首包完整保存在 `release/0.1.21-before-decoder-package-fix`，失败日志和旧助手也留存；冻结时序证据引用的旧 class 通过显式历史迁移映射读取，不拿当前 class 冒充旧身份。

更新后的生产解码器重放原有 1,479 场录音，原客户端、agent、设置和 PCM 身份不变，误差为零；接受清单仍保持相同哈希。原有 16 组原类时序也复用冻结的原始 PCM，通过当前工程请求和渲染器比较，没有再次启动原时序探针。完整世界音乐时序、移动相机投影、硬件输出、macOS 与更多实际设置组合仍待验证；结构生成继续按用户要求暂缓。
