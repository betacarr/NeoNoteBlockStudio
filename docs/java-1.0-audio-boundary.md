# Java 1.0 原始声音管理器边界

官方 Java 1.0 客户端的 `ahm.b(String, float, float, float, float, float)` 与后来的声音引擎有真实差异：先按未截断音量计算声音范围，再把大于 1 的音量截为 1，最后乘以原始 Options 的 sound 设置后交给声音系统。音高在这个方法中原样传递。全局 sound 设置属于源增益，不能套用后来监听器总音量的处理顺序。

[边界记录](verification.md) 保存官方客户端身份、原始类与方法、编译输入、进程结果及 200 个有限输入。原始 SoundManager 方法和原始 SoundPool 查找实际执行；其中 105 个提交播放、95 个因静音或非正音量跳过。源增益、音高和范围按原始浮点位比较。

这个研究探针把声音系统替换为特意不完整的无音频接收端，以记录原方法提交的参数。它没有执行原 Paulscode 混音器，没有打开原生设备，没有测量游戏世界，也没有证明早期资源目录选择、网络事件、监听器坐标或原生上下文等价。Options 分配绕过构造器；原始设置字段另由源码识别。

因此本次不把 Java 1.0 升级为产品中的“源码已核对”声音配置。还需要完成实际资源分发、调用链和原生路径的独立核对。研究用替身仅存在于 `scripts/java/legacy10`，不会被编入桌面声音引擎。

后续独立执行已闭合资源分发与文件选择，见 [Java 1.0 资源选择](java-1.0-resource-selection.md)。这补上资源层的缺口，没有补齐本探针未执行的调用链、原生上下文、解码/混音或世界录音；完整产品声音配置仍未提升。
