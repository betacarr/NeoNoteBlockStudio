# 在播放头拆分片段

选中一个或多个编曲片段，把播放头放到分段位置，然后点击编曲标题栏的「拆分」，或选择「编辑 → 在播放头拆分片段」。默认快捷键是 Ctrl+T；macOS 显示为 Cmd+T，可在快捷键设置中更改或禁用。它是本项目的统一预设，不承诺与 FL Studio 每个同名快捷键一致。

拆分位置始终取点击时的播放头，不随鼠标位置变化，也不会再次吸附。可先拖动标尺定位；播放中也可拆分，输送和已经发出的原音自然尾音继续。

## 范围与选择

只有播放头严格穿过内部、且左右各至少有 1 tick 的所选片段会被拆分；其它所选片段保持原样。播放头在端点或所有范围之外时不增加历史。包含隐藏、锁定或失效成员时，整个操作拒绝，并说明原因。若内部交点不足以形成合法两段，也拒绝整次操作。

拆分后保留左片段的身份，选择对应的右半段；未拆的选中成员仍保留。主片段仅在自己被拆时改为其右半段。一步撤销恢复原片段、完整源和原选择，重做恢复同一批拆分结果。

## 完整内容与独立编辑

分段只改变片段范围。原音符的 tick、音高、时值、力度、声像、音色覆盖和 MIDI 释放信息不被切成两份；跨切点的长音保留原起音和完整时值，右侧不重新触发。NBS / 试听的采样自然尾音也不因新边界截断。

右半段从原源偏移继续，循环相位和周期保持。两段可分别编辑源音符和名称；若旧源还有其它引用，先为拆分的左段分离独立源，保护未选引用。两段均保留完整源和裁剪外内容，拉回边界可重新显示。资源、轨道混音、Delay、全局速度和原始 MIDI 资产保持。

切点上的 MIDI 附加消息只归右侧，避免导出两遍；原先工程末端的消息规则继续保留。源消息未删除，边界归属作为片段参数随 NBSX、片段复制和粘贴保留。见 [工程格式](nbsx-format.md)。

过期的工程、选择或筛选回调不能拆分当前对象。有效数字草稿先提交，再按最新源和范围计算；无效草稿阻止操作。对象数量或工程保存容量超限时，整次拒绝，不留下半次拆分。

## 参考与验证

参考 Ardour 的拆分职责、编辑点与完整源模型，同时采用本项目明确的播放头落点、独立源和选择规则。固定源码及有日期的社区使用反馈见 [DAW 参考](daw-arrangement-reference.md)。本功能不含合并、鼠标切刀或 MIDI 音符拆音工具。

0.1.46 最终通过 1685 项测试（87 文件）。实际界面在固定 tick960 完成多选拆分、撤销／重做、独立改名、锁定／隐藏拒绝与保存重开，共 10 份原始 ZIP 完整读回；另在播放中拆分和撤销，2 份读回保持 23 个原始起音（包括静音守卫）。播放中切点由前后显示位置限定，不冒充固定 tick960 或精确声学时间。

最终 Windows 包使用现有原生菜单与真实保存链路，完成单片段拆分、Undo／Redo、端点拒绝及重启后的 6 份完整 ZIP 读回。物理 Ctrl+T、真实文件对话框操作和扬声器录音不在该脚本范围。实际 GUI 还复现并修复标题换行导致普通点击误跨轨的问题；最终包截图、修复前后与历史构建的范围分别记录在 [验收索引](verification.md)。
