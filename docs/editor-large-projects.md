# 大工程片段预览的修复与验证范围

本轮确认并修复了编曲区缩略音符的两类显示错误：循环超过固定绘制预算后漏画，以及整段画布过宽时没有画出像素。修复限于 `Arrangement`、预览几何助手和画布定位样式；工程数据、循环相位、钢琴编辑行为和音频处理没有改动。来源、原始报告与 fixture 哈希集中记录在[预览证据](verification.md)。

## 已确认的反例

旧 `MiniNotes` 只遍历前 500 个源周期。直接执行归档的原绘图函数，并以实际 `flattenNotes` 展开的播放起音作对照，得到：

| 输入 | 实际播放起音 | 旧缩略图笔画 | 错误 |
| --- | ---: | ---: | --- |
| 源长度 1,920 tick，循环 501 次 | 501 | 500 | 最后一次循环漏画 |
| `offset=501×1920`，副本长度为 4 个源周期 | 4 | 0 | 预算全部花在不可见的早期周期，整个缩略图为空 |

这两份工程都通过工程校验。第二份中的大偏移是合法的已保存数据；修复没有把它改写成取模后的值。旧源码、工程 JSON 与计数保存在 `.local/large-editor-audit/baseline-1792795820532/`，基线报告 SHA256 为 `c50992c6e40f45683c18680953407bca1bfa1c580542eabc0ed9c92e7cf9b354`。

旧画布还按整个片段宽度分配 backing store。MIDI 导入会为每个源轨道/通道建立整首长度的片段，因此视口很窄也可能请求十几万像素宽的画布。独立隐藏 Electron 45.0.0 / Chromium 156.0.8078.48 进程使用真实 Canvas2D 填充，并读取 `(0,0)` 像素，结果如下；所有画布高度均为 42 像素。

| 测试宽度 | 填充后读回 RGBA | 结果 |
| --- | --- | --- |
| 800、21,350、32,767、32,768 | `[23,43,35,255]` | 正常写出像素 |
| 68,136、212,566 | `[0,0,0,0]` | 上下文存在，但未写出预期像素 |

这证明测试过的超宽尺寸会出现实际绘制失败，不能只凭 `getContext('2d')` 非空判定可用。它没有确定 Chromium 的精确宽度阈值，也不代表其他机器、浏览器或高度组合的通用上限。该进程只运行独立画布 fixture，没有加载编辑器或合成界面输入。原始像素报告为 `.local/large-editor-audit/run-1792796123117/canvas-width-report.json`，SHA256 为 `38c248ecbbd9b915b893842123d918d18bc51f80922e1be3192cadd5dc47c7de`。

## 修复方式

[Arrangement](../src/ui/Arrangement.tsx) 按编曲滚动区的横向、纵向可见范围挂载缩略画布。每张画布的 CSS 宽度最多为视口宽度加 4 像素缓冲，backing store 再按设备像素比计算；没有为远处或不可见轨道分配整段画布。

[预览几何助手](../src/ui/arrangement-preview.ts) 保留真实 `offset`，直接求与当前窗口相交的源周期，不再从第零周期消耗固定预算。只有相互重叠的重复笔画会合并为覆盖区间，所有可见音符的覆盖位置仍保留。密集预览因此不保证每个起音都有独立绘图调用，播放数据和起音数量不变。循环分隔线按至少 4 CSS 像素的间隔抽取，只影响装饰线密度。

## 离线检查

[复核脚本](../scripts/audit-large-editor.mjs) 检查了 131 个几何场景：11 个针对性场景覆盖两个原反例、末尾周期、非零相位、远处片段、密集亚像素循环，以及真实导入的 1 万、10 万音符 MIDI 首尾；另有种子 `143144` 生成的 120 个范围/偏移场景。

对照来自实际核心 `flattenNotes` 的起音与显示时值，按音高比较可见笔画区间的并集，全部一致。几何容差为 `1e-7` CSS 像素，用于浮点运算顺序差异；这不是 PCM 对照或音频容差。类型检查和 3 套编辑器测试共 35 项也通过。

完整原始结果为 `.local/large-editor-audit/run-1792796363152/report.json`，SHA256 为 `acc81f5a1fb1e5f327ee2f19799560c9d86b77b3e5439f45a6b8fde20f776099`。对应源码快照保留在该目录的 `source-fixed/`。复核需要本地归档的基线材料与像素报告；它们位于忽略目录 `.local`，不随应用分发。

```powershell
node scripts/audit-large-editor.mjs --baseline .local/large-editor-audit/baseline-1792795820532 --canvas-report .local/large-editor-audit/run-1792796123117/canvas-width-report.json
```

脚本会核对基线源码身份、重跑旧计数反例、检查当前几何，并通过实际 MIDI 导入函数生成大文件结果。重新生成 NBSX 会更新归档时间，因此以已有 fixture 的哈希追踪原始字节。

离线几何、隐藏 renderer 像素检查和这份实际 CUA 记录分别保留，不能互相替代。已有[小窗口滚轮记录](verification.md) 是另一项真实输入检查，也不扩大本轮长片段覆盖范围。

## 尚未证明的性能范围

离线脚本实际导入了 80,026 字节/1 万音符和 800,026 字节/10 万音符的 MIDI。冻结报告中，10 万音符的钢琴绘制会扫描全部 10 万个音符，再扫描 10 万个力度位置，视口内只画出 88 个音符主体；空白处命中检查仍先复制、反转整个音符数组。

该次 Node 检查中，1 万/10 万音符导入耗时约 25.7/236.8 ms；使用记录型画布对象的绘制中位数约 0.36/3.49 ms，实际源码命中检查中位数约 0.11/1.34 ms。计时包含 3 次预热与 11 次采样，但排除了真实 Canvas/GPU、DOM、React 调度及输入延迟，不能换算成编辑器帧率或作为卡顿验收结论。

0.1.16 当时只裁掉不可见画布并修复显示错误，没有加入全轨道虚拟化或源时间索引。上面的冻结报告与计时保留其原始范围。

0.1.33 已为钢琴卷帘加入源时间/音高索引和局部拖动预览，并更新上述脚本以适配当前真实绘制函数；候选工作量与实际操作见 [钢琴编辑响应](piano-responsiveness.md)。

0.1.34 继续为编曲缩略图加入时间/周期相位查询与当前源共享缓存，并缓存轨道、片段、源及音色查找。上述脚本现将真实索引传给几何函数，同时记录查询候选；131 个既有几何场景再次通过。新的独立小数边界、缓存组件与实际大 MIDI 操作见 [编曲区响应](arrangement-responsiveness.md)。目前仍保留全部轨道和片段 DOM，完整虚拟化仍是后续优化范围。
