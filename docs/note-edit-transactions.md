# 音符编辑提交与手势保护

0.1.50 将绘制、移动、拉长、键盘移动／移调、量化和检查器属性修改收敛到同一个音符提交检查。先独立生成候选音符，检查目标关联、锁定、工程字段、源增长、必要的循环展开及保存容量，全部通过后再写工程。回调内部原地修改也在独立候选中执行，错误不能泄漏进原工程。

不合法的整次编辑会显示原因，保留原数据、撤销／重做和选择。失败的新音符不会留下无效选中 ID；语义没有变化时也不增加历史。现有 NBSX 的 1e12 时间字段上界、200 万音符／展开限制、64 MiB 清单与 512 MiB 展开资源容量继续适用，没有新增时间量化。保存预算按实际 24 字节保存时间戳计算，不把采样 Base64 拼进大份 JSON 或解码声音。

源增长规则保持：只有新增或移动起点越过原源长度时才进位增长；时值末端不主动延长源或播放范围。单独修改时值、力度等不会重新改变起音展开数量，旧的过量循环工程仍可调整这些属性以便修复。完整校验包含同一源的其它片段和静音轨，原 MIDI、消息顺序、释放路由、音色与便携采样保留。

钢琴手势现在记录当前工程／历史身份。撤销、重做、工程替换或其它工程提交会使旧手势失效；松手不会覆盖新状态或清空刚产生的重做。手势自身的选音和编辑焦点更新仍可进行。指针捕获及释放过程中发生的同步状态变化也会复核。

数字输入与画布衔接会先确认有效草稿，再用新音符、片段及身份开始手势。输入微调后可直接进行第一次绘制或拖动；无效数字保留在输入框，Esc 可取消，画布不会误编辑。录音追加仍可保留未改变目标的有效数字草稿；其它过期回调继续拒绝。实现只在指针事件入口使用 React 的同步冲刷，不从渲染或 effect 中调用。

本机十万音符加两份便携采样的隔离 Node 量测中，去除预检阶段的 Immer 代理读取后，单次检查约 127～133 ms；单音模型事务约 0.19 秒，全选构造和冻结仍约 0.8 秒。这是候选、检查和 Immer 提交的量测，不包含 React 渲染，也不是帧率保证；钢琴画布预览仍按可见候选工作。

真实旧版界面已复现“草稿保存、首个绘制丢失”。修复后完整保存、分别撤销重做、无效草稿、重开、超界移动／量化和重做保护均有原始 ZIP 回读。持有指针同时撤销的组合通过实际组件回调验证，未称为物理原生输入验收。[证据](verification.md)与[上游参考](daw-arrangement-reference.md)。
