# 原生声音库的平台清单

2026-10-24 按当前目录中的 **103 个正式版**核对 Windows x64、macOS Intel 和 macOS ARM64 的 OpenAL / STB 文件选择。共校验 **51 个不同官方压缩包**：原始版本元数据按官方 URL 中的 SHA-1 校验，库按官方 SHA-1 与大小校验，解包后的文件记录 SHA-256，并检查 PE / Mach-O 的实际 CPU 架构。[完整清单](verification.md) 包含每版元数据、选择结果、原生文件、源码与原始报告哈希。

这次检查发现并修复两个 Mac 资源查找问题：LWJGL 2 使用 `natives-osx`，且库文件名为 `openal.dylib`；原查找使用后来的 `natives-macos` 与 `libopenal.dylib` 约定，漏掉了这些合法文件。现在遵守官方平台映射及系统规则。例如 1.12.2 的 Intel Mac 应选择官方专用的 `2.9.2-nightly-20140822` 包，Windows 则选择 `2.9.4-nightly-20150209`。旧版 Intel 库不会作为 ARM64 库返回。

Mac 的文件边界与 Windows 不同：Intel Mac 的 1.14.4 又切回已出现于 1.14 的原生文件，不能直接继承 Windows 版本分组。ARM64 Mac 的首个匹配 OpenAL 包在当前正式版目录中为 1.19；此前没有匹配包的项目保留明确状态，没有借用 Intel 文件或宣称完成模拟运行。

报告中的 48 个变化条目包含三个平台/架构、两个组件各自的基线与“无匹配包”状态，不能称为 48 次声音引擎更新。STB 包存在也不等于游戏拿它解码音符盒，例如已经独立核对的 1.13 实际使用 Paulscode JOrbis。早期版本的官方现代启动清单还可能含兼容性依赖，清单身份不证明历史发布时的原始分发环境。

本轮没有运行 Mac 二进制，也没有增加原版世界场景或提升声音验收状态。Java 逻辑、JNI 桥、声音资源、解码器注册、上下文设置、平台行为与实测仍须分别核对。Mac 构建、显示、操作及硬件声音见[平台状态](platform-status.md)。
