# 参考音频与录入

参考音频是编曲区中的独立参考轨道，使用同一条拍号标尺、播放线、横向滚动和缩放。导入后可拖动片段标题，或调整轨道左侧的起点来对齐；标题获得焦点后，左右方向键按当前网格移动，Home 回到起点。音量可独立调整，设为零即可静音。移动、音量和移除均可撤销。

拖动参考标题靠近编曲区左右边缘时会自动滚动，向右拖出末尾可临时延展画布。可按 Esc 取消；窗口或目标失焦、工程与时间规则变化也会使旧拖动失效。方向键和 Home 会先取消鼠标预览，再按工程起点操作。见 [拖动取消规则与验收范围](arrangement-gestures.md)。

波形按工程的速度表把真实秒数映射到音乐时间。遇到速度变化，波形在拍格中的宽度随之改变，参考音频本身保持原速。拍号变化与音符共用同一套标尺。波形峰值包含全部声道，右声道独有的声音也会显示。

播放、暂停、停止和循环都使用主输送控制。参考音频不会另开一个独立播放进度。定位会暂停并移动整个工程，再次播放时音符和参考音频都从该位置继续；双击参考波形也可定位。偏移之前保持静音，偏移之后从正确的音频秒数开始。工程试听末尾包含完整参考音频，因此空白工程不会只播完原有一小节便截断参考音频。循环仍须明确启用，并以整个工程末尾为周期；播放时切换循环会从当前位置重新启动同步试听。移动参考音频或修改其音量会暂停试听，修改后按播放继续。

参考音频用于对照试听，保持现有导出语义：WAV、MIDI 和 NBS 导出不混入参考轨道。NBSX 会保存参考音频与起点。当前只有一条参考轨道，起点不能为负；尚未提供音频剪切、拉伸或多个音频片段。

## 电脑键盘与 MIDI

启用录入后，Z–M 对应界面所示的一组半音键，也可使用外部 MIDI 设备。输入框和设置对话框中的电脑键盘输入不会录成音符。

- 停止时为逐步录入：按下时记住当前起点，松开后创建音符，使用工具栏选择的显示时值，并把插入点推进该时值。一起按下的和弦保持共同起点。
- 播放时为实时录入：起点读取音频设备的输送时钟，长度按松开时的实际音乐位置计算。跨越工程循环时会重复应用速度表，不会把回绕后的播放线相减为负时值，也不会按墙钟错误外推下一轮速度。
- 实时录入只写入当前所选片段的播放范围；范围外仍可试听，但不会把音符挤到片段开头。带 offset 的片段会记录到正确的源位置，显式循环片段写回该循环源，循环周期不因录入而延长。录入不生成新片段或演奏分轨。
- 暂停、停止、定位、关闭录入、窗口失焦或设备断开，会先结束并保存当前按住的音符，再改变输送状态。外部 MIDI 按设备与通道区分同音高，避免不同设备的松键相互干扰。关闭录入及卸载时移除 MIDI 监听。
- 已完成的录入可以撤销和重做；停止时一起结束的一组音符作为一次操作保存。显示时值保留演奏长度，仍不会截断原版音符盒采样。

0.1.30 起，普通保存和自动恢复副本也包含尚未松开的音符。保存只截取当时的显示时值，不结束按键或增加撤销记录；继续按住后松开，仍录入完整演奏长度。若松键后的内容与已保存快照完全一致，会自动解除未保存提示；实时演奏继续增长的时值则需要再保存。“保存并关闭”会先结束录入，再保存完整结果。原生保存窗口失焦仍遵循上面的结束录入规则。

按住待录入音符时，即使原工程没有其他修改，也会显示未保存状态；新建或打开其他文件前会询问是否放弃。锁定轨道和片段范围外的按键仅试听，不产生待保存录入。录入过程中若目标片段移动、裁剪、换轨、换源或锁定，松键会提示取消该音符，避免写到已经变化的位置；切换选中片段本身不会改变原来的录入目标。和弦分开松键时，录入自身引起的片段自动延长不会取消其余按键。

电脑键盘每次实际按下只触发一次；停止、失焦或关闭录入结束当前音符后，仍按住同一键产生的系统重复事件不会重新起音，需要松开再按。显示时值与这些保存保护均不改变采样尾音或轨道 Delay 的派生规则。

0.1.31 起，MIDI 录入追加新音符时，正在输入的音符属性和轨道 Delay 数字草稿会继续保留。Enter、失焦或保存时，把确认值写入包含新录音符的最新工程；不会覆盖或删除这些新音符。更换目标、撤销/重做和重新打开工程仍会取消旧目标的草稿。如果录入自动延长了正在编辑的片段长度，该长度栏会刷新为新边界，避免旧草稿覆盖已经增长的范围；其他未改变的音符属性草稿仍可继续编辑。

尚未提供外部 MIDI 延迟校准、量化 note-off、多次循环 take 管理或补录声音实时重渲染。正在播放的音符混音使用启动时的工程快照，新录入音符会即时试听，并在下次启动工程播放时进入完整编曲。没有使用物理 MIDI 硬件验证端到端延迟。

## 验证

0.1.31 另外增加 8 项 App 目标校验与 8 项实际数字组件/App 联动检查，连接真实属性绑定、Delay 面板、录入完成与保存回读。录入前后分别检查草稿文字、待确认状态、完整工程和无效输入拒绝；0.1.30 源码的丢草稿现象单独复现。父级渲染和组件 hooks 是测试替身，不代表挂载 React、原生焦点或 MIDI 硬件验收。详见 [本版证据](verification.md)。

0.1.30 新增 `recording-snapshot.test.ts` 的 39 项核心检查和 `app-recording-save.test.ts` 的 19 项实际 App 源码回调检查，覆盖完整 NBSX 数据、保存先后顺序、逆序和弦、自动恢复回调、目标失效以及数字草稿与关闭保存的组合。时钟、保存窗口完成、失焦和定时器在这些测试中是可控边界，不代表物理 MIDI、原生窗口失焦时机或 GUI 录入验收。最终包另外通过原生菜单/预加载接口的历史与剪贴板回读回归。详见 [本版证据](verification.md)。

`tests/reference-transport.test.ts` 覆盖变速波形与立体声峰值、完整参考时长、偏移与定位、循环边界、跨循环实时录入长度、裁剪源坐标、锁定轨道、异步停止和原生暖机循环的首次播放偏移。

`node scripts/smoke-reference-transport.mjs` 启动独立桌面测试环境，通过真实菜单 IPC 驱动工程并只读观察实际 Web Audio 节点，核对起音时间、暂停保持、变速点定位、4.5 秒循环周期与停止取消。脚本不合成键盘、鼠标、DOM 或 MIDI 事件。原生 PCM 对照由项目的严格游戏音频对照流程独立执行。

发布包复测使用 `node scripts/smoke-reference-transport.mjs --packaged "release/<版本>/win-unpacked/EX NoteBlock Studio.exe"`。此模式不启动开发服务器，直接验证包内界面，并在报告中记录应用版本、打包状态和独立用户目录。
