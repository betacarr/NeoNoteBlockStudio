# 问题反馈与运行日志

遇到无法播放、采样加载失败或异常退出时，先重现问题，再导出诊断包。

![重现问题、打开帮助、保存诊断包、检查后发送的四步示意](assets/guide/diagnostics.svg)

1. 完成导致问题的操作，保留界面提示。
2. 选择 **帮助 → 导出诊断包…**，阅读内容说明，选择保存位置。
3. 解压 ZIP，检查 `README.txt`、`summary.json` 和 `logs/events.jsonl`。
4. 通过原有反馈渠道手动发送，并补充预期行为、实际表现和操作步骤。**程序不会自动上传，不需要维护者搭建服务器。**

界面无法正常工作时，可使用窗口最上方的主程序菜单 **帮助 → 导出诊断包…**。即使渲染界面已崩溃，该入口仍可保存已有记录；无法取得当前播放状态时，诊断包会明确标记。

## 会记录什么

| 内容 | 用途 |
| --- | --- |
| 软件版本、系统版本与架构、运行组件版本 | 确认使用的是哪个发布版与运行环境。 |
| 默认采样数量、缺少的内置音色、资源来源类别 | 判断采样是否加载，是否使用了本机资源。 |
| 播放模式、声音上下文状态、采样率、静音／独奏轨道数量与总音量 | 排查已暂停、音量为零或轨道静音等情况。 |
| 首次非零输出信号、播放失败、错误类型与脱敏堆栈 | 区分音频链路已产生信号与启动失败；非零信号不保证扬声器或系统设备有声。 |
| 界面／子进程异常和关键文件操作失败 | 在界面打不开或异常退出后保留排查线索。 |

不附带工程文件、音符事件、音乐、采样、完整目录清单或环境变量。路径、邮箱和常见凭据在写入前隐藏，导出时再次过滤；自动过滤不能保证识别所有个人信息，发送前仍请检查。

## 本机保存与限制

**帮助 → 打开日志文件夹** 可查看本机日志。不同安装／历史版本的用户资料目录可能不同，不必手工寻找固定路径。

- 普通日志最多 4 份，每份 512 KiB；进程异常记录另限 64 KiB，总上限约 2.1 MiB。
- 导出的记录仅覆盖最近 7 天；普通日志定期清理，进程异常记录在下次启动时清理。
- 重复错误过多时会限流，诊断包会注明丢弃记录数量。
- 日志目录不可写时，编辑和播放继续运行；仍可导出本次会话最近最多 200 条内存记录，并明确标记磁盘日志不可用。
- 系统强制断电、进程被立即终止等情况可能来不及写入最后一条记录。日志不替代 NBSX 保存与恢复副本。

可继续按[隐私与问题报告](../SECURITY.md)提供最小复现；完整工程可能包含原始 MIDI、FLP 与嵌入声音，不应直接作为常规诊断包发送。
