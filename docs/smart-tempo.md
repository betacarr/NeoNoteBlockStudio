# 智能速度

拖入单个音频文件，或使用“文件 → 导入音频文件”，会检测 BPM 和小节重拍（没有可靠的重拍时使用拍点）。BPM 显示在音频片段及其右键菜单中，选中片段时波形上的细线标出首个可见拍点。

导入时自动判断是否采用音频速度：导入位置没有节奏参考时采用检测到的稳定曲速；有重叠的音频、音符片段、速度节点、参考音频或开启节拍器时，只对齐首拍，保留工程速度。

首拍之前的音频会保留。如果放在第 1 小节会丢掉前奏，就把首拍放到能容纳前奏的第一个小节。测不到可靠拍点时，按原位置和速度导入。曲速有明显变化时显示参考 BPM，不自动改工程速度。多文件导入会逐个检测 BPM，但保持批量导入的放置方式和工程速度。

需要手动处理时，右键片段选择“智能速度”，可以重新检测、只对齐首拍，或应用曲速并对齐。已有工程会在片段范围内适配，结束后恢复之前的速度。若音乐被识别成半拍或双倍拍，可在同一菜单修正。应用曲速与移动片段是一项可撤销操作。

检测在本地完成，和和弦分析及分轨是独立任务。使用 [CPJKU Beat This!](https://github.com/CPJKU/beat_this) 1.1.0 的 `small0` 权重（MIT，8.45 MB），在 CPU 上从音频开头最多 90 秒识别节拍与小节重拍，再根据拍点间隔估计 BPM。遇到弱节奏、拍速变化或半拍／双倍拍歧义时，参考值和小节重拍仍可能不准确。当前不生成变速曲线，也不拉伸原音频。

Mac 和 Windows 的本地音频环境安装脚本会配置该模型。已有音频环境可单独用其 Python 执行 `scripts/setup-smart-tempo.py`。安装器校验 PyPI wheel 和上游权重的 SHA-256；推理进程再次校验权重，并用 `weights_only=True` 从本地加载，无需联网。模型不可用时退回基础检测。检测缓存区分模型版本和基础检测，已有片段可用“重新检测曲速与首拍”更新。

本机对照使用 [GTZAN 的人工节拍标注](https://github.com/TempoBeatDownbeat/gtzan_tempo_beat) 与 [GTZAN 音频镜像](https://huggingface.co/datasets/m-a-p/GTZAN)，取镜像测试列表中 blues、classical、hiphop、jazz、pop、rock 各前两段。旧算法 6/12 段有输出，4/12 段与标注 BPM 相差小于 3%；Beat This! 12/12 段有输出，10/12 段在该范围内，另两段为双倍拍。这是本次小样本对照，不是全数据集精度。测试音频不随工程分发。
