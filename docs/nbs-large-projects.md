# NBS 大工程导入与导出

导入时按层重复筛选全部音符，导出时按轨道重复筛选全部播放事件，会使多层工程产生额外开销。本次改为各遍历一次建立分组，保留原来的层内顺序、功能事件判定和导出语义。

独立审计脚本以提交 `82d550f67cf447fc1e26bf828f1a2c717cee7044` 的实际实现作为基线，同时运行当前实现。三组独立编码的 NBS 输入逐项比较工程内容，逐字节比较 NBS 导出结果，并保存和重开 NBSX；全部一致。工程比较只规范化随机 ID 与创建/修改时间，不省略音乐内容、事件、轨道或诊断。

最近一次本机离线记录中，2,048 层、32,768 音符的样例导入由约 143 ms 降为 30 ms，导出由约 2,157 ms 降为 24 ms。另有 64 层和含功能事件的 128 层样例。每项先热身一次，再记录两次运行；这些数值不是界面帧率、跨设备性能保证或最大文件容量。

证据及每次原始计时见 [nbs-scaling.json](verification.md)。运行 `node scripts/audit-nbs-scaling.mjs` 可重新比较，只有显式使用 `--write-evidence` 才更新公开记录。预览画布问题及实际界面检查另见 [大工程编辑](editor-large-projects.md)。
