# FL Studio 工程导入

从“打开 / 导入”选择 `.flp`，或将文件拖入编辑器。先检查音色、采样基准和转换警告，再点“导入为可编辑工程”。取消、解析失败或检查期间工程发生更改，都不会替换当前工程。有未保存修改时，在最终导入前提示处理。

支持采样器以及实际包含离散 MIDI 音符的插件、Layer 等通道，不运行 FL Studio、Python、VST 或原转换工具。导入的是文件内已有音符，不重现插件声音或 Layer 的子通道触发。源码移植自本机 FLP2NBS，MIT 许可随桌面包分发，见 [归属记录](../third_party/flp2nbs/NOTICE.txt)。

## 音色与采样基准

名称只提供音色建议。桌面文件对话框或启动参数打开 FLP 时，会只读核对其中可访问的音频路径；16 种已知 NBS 原版采样的 SHA-256 完全匹配时，自动确认音色与默认基准。不会按文件名认证原版声音，不会修改外部工程或采样。

网页、拖入文件、失效路径、未知采样及手动更改的映射，需要逐声道确认。采样器继续使用原有哈希优先、名称仅建议的规则。其他带音符的通道不按名称或采样哈希猜音色，音色初始为空，需用户填写音色与音高基准并确认；修改后需要重新确认。音频、自动化和没有 MIDI 音符的其他声道不能选入。初始未选入的声道收在折叠区；明确选入可支持的静音声道时，仍保留静音状态。

“采样基准音高”指通道在 FL 根键触发时，对应编辑器的哪个键位。默认输入 66；加 1 升高一个半音，可以输入小数微调。对于非采样器，它是用户指定的音符映射基准，不表示已识别插件音色。它是相对目标音符盒乐器的播放键位，不是对所有采样实际基频的统一判断。FL 根键、通道微调、固定采样移调和音符微调参与换算。实际音高超出 MIDI 0–127 时拒绝导入，不偷偷截断；超出游戏原版两八度范围时，沿用工程的资源包／模组提示。

## 保留的数据

- 原始 PPQ、初始 BPM、四分音符为拍的拍号、音符位置和完整时值。
- 播放列表位置与左右裁剪范围。每次出现的片段、每个选入音符声道转换为独立源副本，之后修改互不关联；不会擅自启用循环。
- 同一 FL 播放列表轨道中的不同音符声道拆开；跨播放列表轨道保留分轨及静音。
- 源片段范围外的音符仍留在钢琴卷帘。播放和导出只读取当前副本范围，因此源音符数可以大于实际播放起音数。
- 原始 FLP 完整字节、来源哈希、转换选择、原通道参数和跳过内容摘要嵌入 NBSX。保存／重开检查原始资源必须存在。

## 转换边界

按初始速度导入离散音符；自动化中的变速、弯音等不应用。音频片段、效果器链、插件声音、通道非线性音量及大部分包络不重现。力度按原值 / 128 换算，声像沿用原工具参数换算；不保证听感或完整播放等价。导入前必须确认警告。

滑音、未知音符标记和未支持的起音／路由参数，需要跳过该声道。采样器的采样范围、拉伸和 Formant 保留原有检查；非采样器只转换文件中的离散音符，不应用采样器专用移调、采样范围、拉伸和 Formant 音频设置。未知参数布局仍拒绝，不从插件状态猜音符。多个 Arrangement、未知片段静音标记、无法确定的裁剪／缩放、损坏或歧义记录等会阻止导入，不猜测恢复。

已实现 FL 20、21、2024、2025、2026 的部分已确认布局。127 个本机真实工程与原 Python 结构解析结果一致，涵盖 240,789 个源音符；这不是对这些版本所有功能或所有工程的兼容认证。遇到尚未确认的布局，例如 FL 25.2+ 的 event 172，会明确拒绝。

单文件最多 128 MiB；解析与导入分别限制事件、音符、片段、分轨和副本数量。检查窗口前另限制片段 × 声道的摘要工作量为 200 万项，防止大量组合占用界面。超限请先拆分源工程。

## 编辑、导出与验收

导入结果可编辑、撤销、设置轨道 Delay、保存为 NBSX，并导出 NBS / MIDI。Delay 在试听和 NBS 导出时生成回声音符，原始导入音符不会被烘焙修改。NBS 起音按所选每拍 8／12 格直接换算，文件头 TPS 按起始 BPM 自动计算；真实细分和格式精度限制分别提示。[音乐格点规则](nbs-musical-timing.md)。NBS 本身不保存音符时值、FL 插件或自动化。

0.1.38 的实际浏览器用本机《本地验证曲目A》完成导入确认、取消、保存／重开、轨道编辑／撤销和 NBS 导出：92 BPM、PPQ 96、6 轨、3,095 个保存的源音符、884 个播放起音。独立解析核对全部位置、时值、音高、力度、声像和导出的 884 个 NBS 事件。该历史导出采用旧时间网格，不能代替当前 8／12 格导出验收。Windows 实包另检查采样哈希识别及真实保存结果的进程重启回读；它没有合成导入确认点击。见 [0.1.38 验收记录](verification.md)。

可用 `scripts/smoke-flp-desktop.mjs --packaged <解包程序> --source <原FLP> --project <实际界面导入后保存的NBSX>` 重跑桌面边界。此验收夹具针对 Java 1.16.5 目标配置；便携新增采样从本机 `1.16.json`、原始 `sounds.json` 和资源对象独立核对，随后做完整工程比较。

0.1.51 再以同一原始 FLP 完成实际映射确认、导入、轨道编辑／撤销、保存重开及当前每拍 8 格 NBS 导出。5 份完整母版及原始 FLP 字节一致，全部 884 个实际导出事件与独立原始解析结果匹配；没有重测原生采样哈希识别或新增 FL 版本认证。[当前贯通验收](editor-workflow-audit.md)。
