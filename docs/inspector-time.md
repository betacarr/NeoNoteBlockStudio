# 时间属性与循环范围

检查器中的开始、显示时值和片段长度均以四分音符为一拍。0.1.32 起，这三个输入会在提交前检查工程时间范围、片段自动延长后的小节边界和展开音符数量。界面的拍数上限随工程 PPQ 换算；精确上限的换算不会因浮点舍入误报超界。

工程中单个时间参数的上限仍为 `1e12` tick。开始与时值分别计算，不要求二者之和小于该值，时值仍不截断音符盒采样。新起音若在源片段范围以外，源尾会按小节延长；因此输入本身未超界，延长后的范围仍可能超过上限并被拒绝。

超过范围或造成超过 200 万个实际展开音符的修改，不会写入工程、增加撤销记录或覆盖原内容。Enter 和保存时保留被拒绝的数字，字段标红并显示待确认；这类数字离开输入框后仍保留，保存、导出或新建不会忽略它。可改为合法值重试，或按 Escape 取消。纯格式无效的输入仍遵循原规则，在普通失焦时恢复模型值；更换目标或撤销也会使旧草稿失效。

更改音高、力度、时值等属性不再因为源中另一个远处音符而延长整个片段。只有新加入或实际移动起音、且新位置超出当前源范围的音符才触发生长；已有音符、MIDI 消息和资源都保留。源尾以内的小数起音不会无故改变循环周期。

循环只计算当前播放范围内实际出现的起音，不遍历偏移之前的空白周期。很大的合法偏移或没有起音的长循环可以正常处理。合法 NBSX 若展开量超限，仍可打开并显示错误提示与“音符展开超限”，可缩短片段长度后继续编辑；源文件中的音符不会因此被删除。渲染或导出仍受实际事件数量限制。

同一时刻重合的同音音符继续遵循原来的片段、循环次数和源音符顺序，避免改变重合乐器和 NBS 层的次序。

验证包括独立朴素循环序列对照、数值边界、实际输入组件与 App 回调、完整 NBSX 回读、开发浏览器中的拒绝/失焦保存/修正/撤销，以及最终 Windows 包的原生菜单与文件流程。原生物理输入、声学效果和性能帧率没有作为这些测试的结论。详见 [0.1.32 证据](verification.md)。
