# Mega 真实音乐试用验收（2026-10-29）

本页保留 v3 自然音乐验收。**当前 v4 已接入更快 CPU 环境，桌面耗时 101.52 秒、峰值 5.32 GB，并完成有独立参考的六来源录音混合检查**，详见 [最新性能与六声部记录](audio-model-performance.md)。自然音乐示例仍无独立参考，后续受控录音检查不能替代它的听感评价。

当前可以本地试用“五类预测＋残余”，不能按成品的互斥六轨交付。真实音乐上已得到明显不同的预测信号；吉他几乎静音，鼓和残余仍有较强相关性。没有独立参考分轨，也没有完成主观听感验收，不能声称六种乐器全部正确分离。

## 素材与许可

使用 [sigsep/spleeter-musdb 的固定提交](https://github.com/sigsep/spleeter-musdb/tree/0a7df2fb3b1c23b5386d0e5e347a673fdd541e63) 根目录 `audio_example.mp3`。README 明确标注音频为 Steven M Bryant ©2011 的 **Slow Motion Dream** 节选，ft CSoul、Alex Beroza、Robert Siekawitch，采用 [CC BY 3.0](https://creativecommons.org/licenses/by/3.0/)；原作地址 <http://dig.ccmixter.org/files/stevieb357/34740>。授权来自音频声明，不能用代码 MIT 替代。

源 SHA256：`4b431d535d235bd81b62f816f08c3f1afb6679d2706d84b3b75903b7df909507`。解码后 479,832 帧、44.1 kHz 立体声、完整 10.880544 秒。修改包括 MP3 解码为 FLOAT WAV、模型分离及相加对比，不对单轨分别归一化。全部在本机处理，没有上传音频或下载 Spleeter 模型。原 MP3 解码后有少量超过 1 的浮点采样，WAV 保留原值；本地对比网页统一设为 80% 音量起播。

## 接入核查与修正

- 官方 `vocal / drums / bass / guitar / piano` 索引为 `[49,15,4,20,33]`。真实音乐前两秒实测，选定五头与完整 53 头前向的对应输出逐采样相同，最大差值 **0**：`.local/effect-eval/head-selection.json`。
- 父子类别存在重叠。没有将 `vocal` 与 lead/back-vocal、`guitar` 与 acoustic/electric-guitar、`drums` 与 kick/snare 等相加。`piano` 没有擅自合并 digital-piano/keys，bass 没有合并 double-bass；单选宽类别避免人为重复求和，不能保证预测自身互斥。
- 官方 `inference.normalize=false`，保留原音量。完整流式解码／重采样至 44.1 kHz 立体声，输出帧数一致。
- 旧 v2 没有遵守官方固定窗口补齐和边界规则。v3 改为上游固定提交 `ea7eb9c` 的 batch=1 通用 demix 配方：20 秒窗口、10 秒步长、2 秒淡化；超过 20 秒时首尾各反射 10 秒；尾段超过半窗时反射补齐，否则补零。所有预测共享重叠权重，再以原混音减五预测得到残余。
- 用磁盘累加器和按需反射读取，避免保存整曲 53 轨张量。缓存升为 `five-residual-v3`，不复用旧结果；完整权重缓存不变。
- `scripts/test_audio_mega.py` 用上下文敏感的确定性模型，对 1、49、50、51、99、100、101、150、201、351 帧的缩小窗口与独立参考算法对照，覆盖短文件、精确边界、反射边界及残余重构。它是算法测试，不替代真实权重验收。

## 真实音乐结果

完整 UI → 文件选择 → IPC → 工作进程 → 真实权重通过。报告 `.local/audio-mega-real-ui/run-YJ8vYL/report.json`：`syntheticInput=false`、`realInference=true`。

| 输出 | RMS（原混音 0.249627） | 相对原混音 RMS | 具体观测 |
| --- | ---: | ---: | --- |
| 人声预测 | 0.114668 | -6.76 dB | 低于 200 Hz 的频谱能量约 0.002% |
| 鼓预测 | 0.048976 | -14.15 dB | 低于 200 Hz 约 90.98%，不能据此证明是完整鼓组 |
| 贝斯预测 | 0.113548 | -6.84 dB | 低于 200 Hz 约 88.32%；与鼓的波形相关约 0.020 |
| 吉他预测 | 0.000088 | -69.05 dB | 几乎静音；不能判断缺失、遗漏还是素材没有明显吉他 |
| 钢琴预测 | 0.105766 | -7.46 dB | 200–2000 Hz 约 88.55%；频谱不能证明没有其他乐器混入 |
| 其他残余 | 0.110559 | -7.07 dB | 与鼓预测波形相关约 0.576、短时 RMS 包络相关约 0.530 |

这些是信号描述，不是能量分配比例、SDR、分类准确率或串轨百分比。相加重构最大误差 `5.96e-8` 只证明对齐和残余计算正确。没有独立参考轨，无法计算可信的声部泄漏率；没有本地音频感知工具，自动播放成功也不等于代理已经听过。可听结论留给实际本地试听，不伪造“听起来干净”。

同一真实输入对照中，v2→v3 的鼓 RMS 从 0.034192 变为 0.048976，残余从 0.127530 变为 0.110559；鼓差值 RMS 为 0.031319。它证明接入配方会明显影响结果，不能据此声称听感必然改善。记录 `.local/effect-eval/listening/signal-report.json`。

## 试听与资源边界

`scripts/start-audio-trial.cmd` 复用已下载的独立 QA 配置并打开真实音乐工程。工程 `.local/audio-mega-real-ui/run-YJ8vYL/real-mega-six-output.nbsx` 必须与同名 `.nbsx.assets` 目录一起保留；不改日常用户工程或重下载模型。

浏览器可打开 `.local/effect-eval/listening/listen.html`，比较原混音、五预测、残余、五预测之和及六输出之和；同目录 WAV 带完整署名与许可，只本地读取。`scripts/analyze-audio-mega-effects.py` 可重建对比文件和测量。

10.88 秒实曲：加载 **8.86 秒**，两窗前向 **175.42 秒**，模型流程 **186.38 秒**，桌面总耗时 **197.84 秒**；峰值工作集 **16.42 GB**（15.29 GiB）。CPU 8 线程，PyTorch 2.0.1+cpu，无 CUDA。不能用旧可变短窗的约 8 GB 推断新版内存需求；16 GB 总内存机器可能没有足够余量，其他机器和 GPU 尚未实测。

播放推进、静音／独奏、单轨 FLOAT WAV 导出、保存 7 个工程旁资源及真实重开通过。另一次任务在真正前向开始后取消，约 **0.05 秒**结束并移除该任务 pending 目录，保留先前六条波形，没有终止用户其他进程。

21 秒压力输入由同一节选循环构成，只测跨窗口、反射边界和内存，不冒充自然长曲或增加语义样本数。实际完成 5 个 20 秒窗口：总耗时 **447.20 秒**，峰值工作集 **16.458 GB**，第二窗起保持稳定；六个输出均为完整 926,100 帧，重构误差低于 `1e-6`，临时累加文件已清理。报告 `.local/effect-eval/real-music-v3-stress-21s/stress-report.json` 同时保存逐窗耗时、文件哈希和 10／20 秒边界采样差值。

更长歌曲按 10 秒步长增加模型调用，允许导入两小时不等于已证明两小时歌曲可以实用地跑完。播放器另有 2 GiB 全缓冲预算；后台磁盘累加不代表试听也流式处理。完整长曲、GPU、吉他有效分离和主观听感仍未验收。

本轮验证：Python 数值配方测试 2 项（含 10 种长度边界）通过；受影响的 5 个音频 Vitest 文件共 64 项最终通过，类型检查和 Electron 构建通过。首次并发回归中两项 localhost 下载测试出现断流／5 秒超时，随后单独两项及整组 64 项重跑通过，本轮效果修订没有为此修改下载器，也没有重下载官方资源。先前 2179 项全套回归属于上一阶段，不能当作本轮已重复全套。
